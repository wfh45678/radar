# ES 7.17 → 8.18 升级方案（roadmap P1-3 收口）

## Context

ES client 7.17 是 RestHighLevelClient 的最终版本（8.x 已整体删除，停止演进）。roadmap P1-3 当年暂缓的前提（依赖 P0-1 测试基建）现已成立：7 个集成测试经 Testcontainers 全链路触 ES（写入→hitsSort count→event query→建索引），回归面可自动化验证。本次升级：

- 服务端：ES 7.17.15 → **8.18.8**（与 Boot 3.5.16 BOM 托管的 elasticsearch-java 8.18.8 同 minor）
- 客户端：RestHighLevelClient → **co.elastic.clients ElasticsearchClient**（官方新客户端，类型安全 lambda DSL）
- 存量数据：不做自动迁移工具——事件检索数据可从 Mongo 全量重建（operations.md 已确认逃生门），升级指南写明 reindex-from-remote 与重建两条路径
- 版本：主 pom 3.5.1→(跳过远端已用的 5.x 之外的冲突)……主 pom 实际是 3.5.1 但远端已发 5.1.1——升级落地为 **v5.2.0**（infra 大版本演进，随 CHANGELOG/发布说明）

## 现状要点（探索实证）

- pom 自管 `<es.version>7.17.29` 三坐标（RHLC + server 核心 jar + rest-client），完全脱管 Boot BOM；主类已排除 Boot ES 自动装配——升级无 BOM 冲突，反而可删显式版本直接用 Boot 托管 8.18.8
- ES 使用面收敛在 7 个文件，无 Bulk/Get/Delete API；核心重写仅 2 个（EsConfig + SearchEngineServiceImpl），其余 4 个机械替换；`ScenarioServiceImpl.buildEsMappingJson` 产纯 JSON 字符串，8.x 照收，零改动
- `RuleServiceImpl.getHitSorts` 是逐规则 count（N 次往返），非真聚合——本次顺手不动（列 backlog）
- 8.x 默认开启 xpack security：compose 与 Testcontainers 必须显式 `xpack.security.enabled=false`（Test 环境已有该 env）

## 实施内容

### 1. pom（依赖对齐 Boot BOM）

- 删 `<es.version>7.17.29` 属性与三坐标（RHLC / org.elasticsearch:elasticsearch / rest-client 7.17.29）
- 新增（无版本，随 Boot 3.5 BOM → 8.18.8）：
  - `co.elastic.clients:elasticsearch-java`
  - `org.elasticsearch.client:elasticsearch-rest-client`（低层传输，EsConfig 复用）
- `httpclient 4.5.14` 保留（低层 rest-client 传输依赖；编译验证后若冗余可删）
- 主 pom 版本 → **5.2.0**

### 2. EsConfig（保留认证/URL 装配，换客户端）

- 保留 `elasticsearch.url/username/password` 自定义属性与 Basic 认证分支
- 新 bean：低层 `RestClient`（HttpHost.create(url) + 凭证逻辑原样）→ `RestClientTransport(restClient, new JacksonJsonpMapper())` → `ElasticsearchClient`
- 顺手补 connect/socket 超时配置（原来缺失，`RestClient.builder(...).setRequestConfigCallback`）

### 3. SearchEngineService/Impl（核心重写，接口瘦身）

- 接口去 ES 类型泄漏：新增结果模型 `SearchResult { long total; List<String> sources; }`（service/search 包）
- 签名改为：`SearchResult search(index, Query query, Query filter, offset, limit)`、`long count(index, Query query, Query postFilter)`、`indexExist/createIndex(index, alias, mappingJson)/deleteIndex`
  —— `Query`（co.elastic.clients DSL）保留在签名中（调用方均为内部引擎类，避免过度抽象）
- 实现：`ElasticsearchClient.search(s -> s.index(index).query(query).postFilter(filter).from().size().explain(true))`；hits 源经 `hit.source()` → JsonData → JSON 字符串；`indices().exists/create/delete`（create 收 mappingJson 字符串，先删后建逻辑不变）；死代码 `aggregateByTerms/avg/max` 删除
- `SearchType.DFS_QUERY_THEN_FETCH` 若 DSL 不支持直接省略（语义无损）

### 4. 机械替换（3 个调用文件）

- `RiskResultAsyncService`：`client.index(i -> i.index(guid.toLowerCase()).id(reqId).withJson(jsonStr))`
- `EventServiceImpl`：`Query.of(q -> q.term(...)/range(...))`；`hit.source()` JSON 字符串化后原有 fastjson2 解析不变
- `RuleServiceImpl.getHitSorts`：同样 `Query.of` 两处（逐规则 count 的 N 次往返优化列 backlog 不动）

### 5. 基础设施（server 同升）

- docker-compose.yml：ES 镜像 `7.17.15` → `8.18.8`，显式加 `xpack.security.enabled=false`，app 的 `ELASTICSEARCH_URL` 不变
- `AbstractIntegrationTest`：Testcontainers 镜像同步 8.18.8（security env 已有）
- 7 个集成测试（InfraSmoke/EngineFullChain/ScenarioPackage/TemplateRedLine/MapStruct/PluginTest 等）直接回归

### 6. 文档与版本

- `docs/upgrade-guide.md` 新增 **ES 7→8 章节**：服务端升级路径（原地升级要求/reindex-from-remote/由 Mongo 重建三条路径）+ compose 变更 + 客户端 API 断点对照表
- `CHANGELOG.md` v5.2.0 条目；roadmap P1-3 标注已实施（v5.2.0）
- operations.md：ES 排查段补充 8.x 安全默认值说明

## 验证

1. `mvn test`：L1/L2 全绿（68+ 例）
2. `mvn verify`（CI/Docker 环境）：7 个集成测试全过——覆盖写入→hitsSort count→event query→建索引重建全链路
3. docker compose up：ES 8.18.8 健康检查通过，事件上传→检索→报表链路手工冒烟
4. `grep -r RestHighLevelClient src/` 零残留；`grep -r "7.17" pom.xml docker-compose.yml` 零残留

## 风险与对策

| 风险 | 对策 |
|---|---|
| 新客户端 API 语义差异（source 反序列化/explain/searchType） | 集成测试全链路回归覆盖全部触点 |
| ES 8 默认安全（TLS+认证） | compose/Test 显式关闭 security；EsConfig 认证分支本已具备（生产带密码可用） |
| client 8.18 vs server 8.x minor 错配 | server 镜像锁 8.18.8 与 client 同 minor；upgrade-guide 注明对齐要求 |
| httpclient 4.5 冗余/缺失 | 编译验证；rest-client 8.x 自带所需传递依赖则删显式声明 |
| 存量索引不兼容 | 升级指南三条路径（reindex-from-remote/快照/Mongo 重建），不写自动迁移工具 |
