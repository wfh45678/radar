# Radar v3.4 实施方案：官方策略包模板库

> 版本：v1.1（2026-11-23：分发模式定案 B——内置基线 + 配置化在线源，默认关）
> 范围：官方场景模板制作（3 个）+ 模板内置分发（jar resources）+ 配置化在线模板源 + 管理端模板库（浏览/一键创建）+ 模板导入端点；官方托管地址上线、模板市场社区投稿不在本版
> 状态：方案评审稿
> 前置：v3.2 策略包已发布（信封/导入引擎/校验报告已闭环）；roadmap P2-7 拉伸项转正（立项 v3.4）

---

## 1. 背景与定位

v3.2 给了模型一个文件形态（策略包），解决了"怎么分享"；但生态还缺"分享什么"——用户装完 Radar
面对空白模型列表，从零配一套字段/名单/抽象/规则的成本高，开源产品的"十分钟可体验"断层在这里。

官方模板库 = 用 v3.2 的策略包承载 3~5 个开箱即用的场景风控模板，随 jar 内置分发，管理端
一键浏览、一键创建为可编辑副本。它同时是：

1. **新用户的第一公里**：装好即有完整可跑的场景模型（字段→名单→抽象→规则→命中）；
2. **策略包格式的示范样本**：模板即最佳实践文档，比 markdown 更有说服力；
3. **模板生态的种子**：格式标准化后，社区投稿模板（issue/PR 附 json）天然可行。

纯增量功能：信封格式不动（`formatVersion` 1.0 不变）、无 schema 变更、无 API 破坏，minor bump。

## 3. 技术决策（待评审确认）

| 决策 | 选择 | 理由 |
|------|------|------|
| 分发方式 | **内置基线 + 配置化在线源**（2026-11-23 拍板 B）：`src/main/resources/models/*.json` + `catalog.json` 随 jar 分发；`sys.conf.template-source-url` 配置远程 catalog 地址，**默认空 = 仅内置，离线/内网零行为变化** | 内置保底可用；在线源让官方上新不走发版（内容运营节奏）。托管地址本期不硬编码——配置驱动，官方地址就绪后在文档公布（建议 riskengine.cn 静态托管，国内可达；jsDelivr 可作镜像） |
| 远程源协议 | 纯静态：catalog.json + 包体 json 两个 GET，无服务端 API | 官方侧维护成本=推静态文件到托管目录；无后端、无鉴权面。包体地址相对 catalog URL 解析 |
| 在线源失败路径 | 列表请求时拉取（3s 超时）→ 失败仅显示内置 + 前端标"在线源不可用"；负缓存 60s 防重试风暴 | 降级永远可用；不给应用启动和核心链路引入网络依赖 |
| key 冲突 | 合并列表中**远程同名 key 覆盖内置**（卡片标"在线"徽标）；导入按合并结果解析 | 官方可在线修订有问题的模板，不必等发版 |
| 信封格式 | **不改**：模板 json 就是普通策略包 | formatVersion 冻结；模板与用户导出的包格式完全一致，心智零成本 |
| 模板元数据 | `catalog.json` 承载（key/名称/场景/描述/标签/最低版本），内置与远程同构 | 分发元数据不污染数据格式；启动扫描内置 + 内存缓存（个位数文件，体量可忽略） |
| 导入路径 | **复用** `validate` + `importPackage`，零新导入逻辑；远程包体同样过 10MB 上限与结构校验 | 模板导入 = 特定来源的普通导入，校验报告/事务/重映射全部白拿；拉取 URL 来自管理员配置而非匿名输入，无 SSRF 面 |
| 插件约束 | 模板**仅使用 BUILTIN_V3 内置插件**（含 v3.0 迁移的 8 个） | 全新安装导入必须零警告——这是模板质量红线，缺插件告警的模板不许入库 |
| 名单策略 | 名单只做**结构种子**（字段定义 + ≤10 行示例数据或空表），规则以抽象频控为主 | 黑名单数据会陈旧，模板价值在策略结构不在数据 |
| 内容边界 | 全部模板从零搭建（在测试服务器上用 v3.2 导出功能制作），不携带任何真实数据 | 模板即官方内容，敏感性要求等同源码 |

### 首发模板清单（3 个，可调整）

| key | 场景 | 策略要点 |
|-----|------|----------|
| `account-takeover` | 账户盗用/暴力破解 | IP/设备/用户三维登录频控抽象 + 失败集中检测 + 分级处置（reject/review） |
| `transaction-risk` | 交易风控 | 大额 + 非常用时段 + 异地（IP2LOCATION/GPS2LOCATION）组合规则，名单：金额阈值参数表 |
| `promo-abuse` | 营销反作弊 | 注册领奖批量小号：设备聚集 + IP 聚集 + 用户名/手机号模式规则 |

## 4. 实施内容

### 4.1 T1：模板分发基建（后端）

- `resources/models/catalog.json`：内置模板索引（key/file/name/description/tags/minRadarVersion）
- `TemplateCatalogService`：启动扫描解析（catalog + 各包 `parse` 预校验），缓存 `List<TemplateInfo>`（含规则数/名单数统计供卡片展示）；单文件损坏只告警不阻断启动
- `TemplateSourceService`（在线源）：`sys.conf.template-source-url` 非空时启用；拉远程 catalog（3s 超时 + 60s 负缓存）→ 按 key 合并（远程覆盖内置）→ 包体按相对地址懒拉取；任一失败降级为仅内置并带状态标记

### 4.2 T2：端点

- `GET /services/v1/model/templates`：模板卡片列表（内置 + 在线合并，含来源徽标与源状态；元数据 + 统计，不含包体）
- `POST /services/v1/model/templates/{key}/import`：按 key 在合并结果中解析来源 → 加载（classpath / 远程懒拉取）→ `validate` → `importPackage`，表单参数与 `/import` 一致（label/merchantCode/modelName，后端给默认预填值），返回新模型 id + warnings——响应结构与现有导入完全一致

### 4.3 T3：前端（ModelList + 模板库弹窗）

- 页头新增"模板库"按钮 → 弹窗卡片列表（名称/场景标签/描述/规则·名单统计/来源徽标；顶部细字标注在线源状态：已连接 / 不可用·仅内置 / 未配置）
- 卡片"一键创建" → 内嵌表单（label/merchantCode/modelName 预填模板默认值）→ 提交 → 校验报告回显（复用 ImportModel 的结果展示）→ 刷新列表
- `ImportModel.jsx` 的结果展示段抽公共组件，两弹窗共用

### 4.4 T4：模板内容制作（S3 主体，工程外工作）

- 在测试服务器（124.221.202.39，已是开源版专属环境）从零搭建 3 个场景模型：字段 → 名单结构 → 抽象频控 → 规则（Groovy）→ 造事件验证命中路径
- `GET /export/{id}` 导出 → 清洗核对（label/merchantCode 改模板语义、无真实数据、插件全内置）→ 入 `resources/models/` + catalog 条目
- 每模板附一段"策略说明"（catalog.description，说明防线设计，不是使用手册）

### 4.5 T5：测试

- L1：catalog 解析/损坏文件降级/模板导入端点；在线源（本地 mock http 服务）：正常合并、key 覆盖、超时降级、负缓存、包体拉取导入
- L3：**每个内置模板**在干净 Testcontainers 环境导入 → 零 error 级 warnings → build 通过 → 造一条事件命中预期规则；模板质量红线即用例化
- e2e（拉伸）：smoke.spec.ts 增加模板库打开 + 一键创建一步

### 4.6 T6：文档与发布

- `docs/model-package.md` 增"官方模板库"节；VitePress 文档站快速开始引导"从模板创建第一个模型"
- roadmap v1.5：P2-6 补记已完成、P2-7 拉伸项转正记录（立项 v3.4）
- CHANGELOG、主 pom 3.4.0、tag 发布（复用流水线）

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| 模板在全新环境导入告警（缺插件/Groovy 不兼容） | 质量红线 = L3 干净环境零 error 导入 + build + 命中验证，用例化后随 CI 常驻 |
| 在线源成为可用性负担 | 默认关（不配置 = 纯内置）；拉取只发生在打开模板库时，超时/降级/负缓存三保险；永不阻塞启动与核心链路 |
| 远程模板内容风险（被篡改/与版本不兼容） | 与用户上传导入同一信任模型（管理员配置源 + validate + Groovy 构建兜底）；formatVersion 校验拒绝过新格式；官方源地址经文档公布，建议 HTTPS 托管 |
| 官方托管地址未就绪拖住发布 | 不硬编码默认 URL——功能配置驱动，发布不被托管上线阻塞；地址就绪后文档补充 |
| 模板内容与用户场景不匹配没人用 | 首发 3 个选最通用场景；描述写清"防线设计思路"，模板是起点不是终点 |
| 名单示例数据被误当生产数据 | 名单仅结构种子（≤10 行且值明显占位，如 `1.2.3.4`）；说明文案明示 |
| Groovy 脚本随引擎演进失效 | 模板随版本发布同生命周期；L3 build 兜底 + 校验报告预编译检查；在线源可热修 |
| jar 体积膨胀 | 3~5 个 json 级模板总计 <1MB，忽略不计 |
| catalog 与包体不一致（改了包忘改索引） | 启动时以包体解析为准计算统计，catalog 仅存展示元数据；S4 用例校验两者 key 一致 |

## 7. 验收标准

1. 全新部署（radar-init.sql + 默认插件）打开模板库 → 3 个模板卡片可见 → 各一键创建 → 零 error 警告 → build 通过
2. 每个模板造一条预期事件，规则按设计命中（account-takeover 高频登录 reject；transaction-risk 大额命中；promo-abuse 批量注册命中）
3. 模板创建的模型可正常编辑、导出（再导出仍是合法策略包，round-trip 不劣化）
4. 损坏模板文件不阻断应用启动，管理端该模板不可见且日志告警
5. **在线源**：配置合法地址后列表出现远程模板且可一键创建（远程 key 覆盖内置生效）；地址不可达/超时时仅显示内置并有"在线源不可用"提示；不配置时与纯内置行为完全一致
6. L1/L2 全绿 + 覆盖率门禁（≥40%）保持；v3.4.0 按发布规范（tag + CHANGELOG + Release + GHCR + Central 幂等）
